**Status:** decisions made: nickname leaderboards, no age gate, existing art plus simple shapes, currency "Candles",

Decisions so far: **mini-games with the ghosts**, **cloud save with accounts**, **design first**.
Constraints that still hold: free hosting (GitHub Pages + Cloudflare), no Node (Python tooling, plain ES modules),
no pet names / "just a bot" lines, character ids are numbers, nothing secret in the repo.

## 1. The idea in one paragraph
Each ghost has one short mini-game that fits her personality. Playing earns **Candles** (soft currency) and
**Bond XP** with that ghost. A higher bond unlocks small things in chat (new greetings, moods, a ghost story,
a stage background). Daily quests and a streak bring people back; achievements and weekly leaderboards give
goals. Progress is saved to an account, so it follows the player across devices.

## 2. Mini-games (no Gemini calls: they cost nothing to run)
| Ghost | Game | Core mechanic | Why it fits |
|---|---|---|---|
| 1 Pocomon | **Hop Hop** | one-button endless runner: hop over obstacles, score = distance | a pocong can only hop |
| 2 Ngesomon | **Night Rounds** | tap the rooms that light up before their timers run out | a busy nurse on shift |
| 3 Sundemon | **Quiet Wish** | slow memory sequence (Simon): repeat the glowing petals, no timer, no fail screen | calm and wistful |
| 4 Kuntimon | **Hair Catch** | move left and right to catch falling secrets with her hair, avoid the duds | curious about everything |

Each is a small canvas or DOM game in `assets/scripts/games/<id>.js`, about 150 to 300 lines, using the existing
cutout art plus a few simple shapes. Every game ends with a result screen: score, Candles, Bond XP, the ghost's
reaction line (written per character, EN and ID, like `busy` today).

## 3. Progression
- **Candles:** earned per run (capped per day) and from quests. Spent on cosmetic unlocks only. No pay-to-win and no real money.
- **Bond (per ghost):** XP from games and from chatting (a small amount per message, capped per day). Levels 1 to 10.
  Rewards by level: new greeting lines, a "mood" line set, a short ghost story, a stage background.
- **Daily quests (3 a day):** e.g. "play any game once", "chat with Kuntimon", "beat 500 in Hop Hop".
- **Streak:** consecutive days with a quest done. A missed day resets it. No punishing pop-ups.
- **Achievements:** about 20 badges (first win, play all four games, seven-day streak, bond level 5 with everyone).
- **Leaderboards:** weekly top 20 per game (display name only). Cosmetic: scores are client-reported (see section 6).

## 4. Accounts and storage
- **Sign-in:** "Sign in with Google" (Google Identity Services). The Worker verifies Google's ID token. No passwords to
  store or leak and no email sending to set up. Optional later: email magic link.
- **Guest first:** anyone can play right away; progress sits in this browser. When they sign in, local progress is
  merged into the account (take the higher value per item).
- **Session:** a signed, `HttpOnly`, `Secure`, `SameSite=Lax` cookie on `.securhat.com`. The site
  (`omonomon.securhat.com`) and the API host are the same site, so the cookie works with CORS credentials.
- **Database:** Cloudflare **D1** (SQLite). Free tier is far above what this needs.
  Tables: `users`, `bonds`, `runs`, `quests`, `achievements`, `wallet_log`.
- **API:** a second Worker (`omonomon-api`, at `apimon.securhat.com`) separate from the Gemini Worker (`omonomon-gemini`) so a games
  bug or flood can never touch the Gemini budget. Same rate-limit binding approach, Turnstile on first sign-in.
- **Chat logs stay unlinked from accounts.** The Axiom request log keeps no account id, so game profiles and
  chat text are never joined.

## 5. Pages and routes (extends the router)
| Address | Page | Indexed |
|---|---|---|
| `/games/` | game hub: four games, daily quests, streak | yes |
| `/games/<slug>/` e.g. `/games/hop-hop/` | one game | yes |
| `/me/` | profile: bonds, badges, Candles, settings, delete account | no |
| `/leaderboard/` | weekly boards | yes |

Pages are generated by `tools/make_site.py` like the character pages; the sitemap and structured data are extended.
The app is WhatsApp-style: `/` is the chat list, with a bottom tab bar (Chats, Games, Me). Games and Privacy live in the tabs.

## 6. Risks and how we handle them
- **Cheating:** scores come from the browser, so anyone can fake one. Mitigation: server-side plausibility caps per game,
  one score submission per run token, rate limits, and keeping leaderboards cosmetic (no valuable prizes). Deterministic
  replay verification is possible later but is a lot of work.
- **Privacy law:** accounts mean storing personal data (name, email, Google id). Needs a real privacy page, a clear purpose,
  data export and **delete account**, short retention for logs, and a decision on minors (see questions). Not legal advice.
- **Abuse and cost:** free-tier limits (Workers 100k requests a day, D1 writes 100k a day). Run submissions are batched and rate limited.
- **Scope creep:** four games is a lot of art and tuning. We build and test one before the rest.

## 7. Build order (each step is shippable)
1. **Foundation:** privacy page, `/games/` hub shell, games router, shared result screen, Bond/Candle model in `localStorage`.
2. **Game 1: Hop Hop** end to end (guest mode). Tune until it is fun.
3. **Accounts:** `omonomon-api` Worker, D1 schema, Google sign-in, save/load, guest merge, delete account.
4. **Games 2 to 4** (Night Rounds, Quiet Wish, Hair Catch).
5. **Quests, streak, achievements** and the chat unlocks tied to Bond levels.
6. **Leaderboards**, anti-cheat caps, polish, Axiom dashboards for the API Worker.
